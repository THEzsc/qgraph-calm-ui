# 界面规则

## 用户确认与反例

用户否定的首版：浅色、圆角、蓝色按钮，但充满宣传标题、常驻侧栏、百分比、状态标签和重复卡片边框。仅减少饱和度不解决信息密度问题。

用户认可的修订：顶部细工具栏，文档成为中心，右侧问题直接排版，默认只展开一个回答；底部单一提问入口。随后选定 03「连点」图标。

## 层级与布局

- 背景使用接近中性的浅灰；白色文档与背景通过轻微阴影分开。
- 桌面参考：工具栏约 64–70 px；文档阅读宽度约 300–520 px，关联问题约 220–310 px。间距随窗口调整，不把这些数值当成通用模板尺寸。
- 原文保留文档自身字体。参考里的衬线大标题属于论文页，不是应用导航的字体风格。
- 问题区使用无边框标题、简短回答与稀疏分隔线。展开状态用可旋转的箭头提示；其他问题保留标题。
- 小屏改为文档在上、问题在下，浮动提问栏留足底部空间。保留阅读／探索切换，不强行缩小两栏。
- 侧栏按需出现。若改成覆盖层，提供关闭入口和 Escape；如果遮挡主任务，明确焦点与点击遮罩行为。

## 参考值

| 角色 | 样机基准 |
| --- | --- |
| 画布 | `#f5f5f7` |
| 内容 | `#ffffff` |
| 主文字 | `#1d1d1f` |
| 次要文字 | `#77777d`，按实际背景检查对比度 |
| 辅助信息 | `#86868b`，关键内容不能仅依赖浅灰 |
| 动作色 | `#007aff` |
| 分隔线 | `#dedee3` |
| 界面字体 | 系统无衬线字体 |
| UI 标题 | 13–17 px，500–600 字重 |
| UI 正文 | 12–14 px，较疏行距 |
| 文档表面 | 约 4 px 小圆角、轻阴影 |
| 分段控件 | 外 8 px，内 6 px |
| 提问栏 | 胶囊形，发送按钮圆形 |

这些是浅色参考值，不是已验证的完整无障碍配色或暗色系统。扩展暗色、高对比度或更大字体时按语义重新校准，而非机械反色。

## 文案与功能

- 一句话先给出回答核心，推导和来源逐层显示。
- Q Graph 的主要动词：阅读、探索、提问、连接。用这些动作组织控件，不增加没有功能理由的标签。
- 空状态解释下一步；加载状态表明实际进展；失败提供真实重试路径。样机未实现的功能明确标记。
- 文档原文、用户引文与 AI 回答不能为了视觉简洁随意删改。压缩界面说明文案，不牺牲内容忠实性。
- 保留关联的真实性：不能为了好看添加无数据依据的连线、来源、置信度或问题。
